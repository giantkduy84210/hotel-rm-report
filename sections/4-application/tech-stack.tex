\paragraph{Why not Excel or Power BI.}
A spreadsheet is the default tool for small analytical projects, but the theory explicitly identifies its limitation: a spreadsheet-based model base has ``\emph{no catalog, no uniform invocation, no run record}'' --- the three things an MBMS must provide --- and practice confirms that hotels running revenue management on ``\emph{a series of Excel spreadsheets}'' see success ``\emph{largely dependent on the caliber of the person}'' responsible~\cite{anderson2012}. Power BI provides a richer visual layer but presumes a server-hosted data model and does not expose the model-base interface our MBMS design requires. The Python/DuckDB/Streamlit stack was chosen because it implements all four subsystems of Turban's architecture --- data management, model management, user interface, and knowledge --- with no component left to improvisation, while remaining proportionate to the project's scale.
